# ADR-0003: 测试策略决策

## 状态

已接受

## 决策标题

采用分层测试策略，重点测试业务逻辑

## 上下文

需要为 Muse 建立完整的测试策略，目标：
- 确保核心功能的正确性
- 支持持续集成
- 平衡测试覆盖率和开发效率

## 决策

采用 **测试金字塔** 模型，按优先级测试：

```
        ┌─────────┐
        │ UI 测试  │  ← 关键用户流程
        ├─────────┤
        │ 集成测试  │  ← 组件交互
        ├─────────┤
        │ 单元测试  │  ← 业务逻辑（重点）
        └─────────┘
```

### 测试分布

| 层次 | 覆盖率目标 | 工具 |
|------|-----------|------|
| 单元测试 | 80% | JUnit、MockK、Turbine |
| 集成测试 | 50% | AndroidJUnit、Room Testing |
| UI 测试 | 关键路径 | Compose Test、Espresso |

### 测试范围

#### 单元测试（重点）

- ViewModel 逻辑
- Repository 数据操作
- UseCase 业务规则
- 数据模型转换
- 网络响应解析

#### 集成测试

- 数据库迁移
- UI 组件渲染
- WorkManager 任务

#### UI 测试

- 关键用户流程
- 导航逻辑
- 权限处理

## 后果

### 正面影响

- **快速反馈**: 单元测试运行快，开发效率高
- **可靠部署**: CI 自动运行测试，减少线上问题
- **重构信心**: 完善的测试覆盖支持安全重构

### 负面影响

- **维护成本**: 测试代码需要随功能更新
- **编写时间**: 初期需要投入时间编写测试
- **Mock 复杂度**: 某些场景 Mock 设置复杂

### 风险缓解

- 提供测试模板和示例
- CI 自动运行测试
- 定期审查测试质量
